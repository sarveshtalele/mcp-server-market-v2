## 1. What this project is

A **proof of concept**: a synthetic stock-exchange dataset exposed as an MCP server, consumed by (a) external AI hosts — Claude Desktop, Claude Code, VS Code Copilot, Antigravity — and (b) this repo's own Next.js chat UI, which renders live tool telemetry.

It is **not** a market-data product. The data is generated by `Faker` with `SEED = 2025`. Never present it as real, and never let the UI imply it is.

**Status:** the migration to MCP **`2026-07-28`** has landed. `MIGRATION_PLAN.md` records why the architecture looks like this and what was rejected along the way; `IMPLEMENTATION_PLAN.md` records how it was executed.

## 2. Non-negotiable invariants

Break any of these and the PoC stops working, usually silently.

1. **Seeded data is frozen.** `core/seed.py` `SEED = 2025`, `modules/listings/seed.py` `shares_band`. A migration that changes one seeded number invalidates every golden test and every screenshot. `market_cap = price × shares`, and `shares_outstanding` is per-company banded — a flat band makes cross-company comparison meaningless.
2. **Nothing writes to stdout.** All logging goes to stderr (`core/logging_config.py`). On stdio transport, stdout *is* the JSON-RPC channel; one stray `print` corrupts the session.
3. **Tool data is the only source of truth.** The server's `instructions` string and the agent's `SYSTEM_PROMPT` both say: answer only from tool results, and say so explicitly when a call fails. `instructions` is advisory (MCP cannot enforce it on a host you don't control); `SYSTEM_PROMPT` is the enforced one.
4. **Two timings, never conflated.** Client-measured per-tool `ms` (from AG-UI `TOOL_CALL_START`/`RESULT` timestamps, computed in `ControlRoomChat.tsx`) and backend-measured end-to-end `elapsedMs` + token usage (one `CUSTOM` AG-UI event per run from `agui_agent/agent.py`, surfaced as `Msg.usage`).
5. **The UI shows only what the backend actually reports.** No fabricated token counts, no invented agents, no fake latency. Demo fixtures must be labelled `DEMO`.
6. **Adding a module must not require editing shared code.** See §5.
7. **Every MCP consumer goes through the gateway.** No host config, and no internal client, may point straight at `:8000/mcp`. A call that bypasses `:3111` is a call nobody can audit — which defeats the product's whole premise. This has already happened once by accident (see §9).

## 3. Architecture


```
Claude Desktop ─┐
Claude Code    ─┤
VS Code Copilot─┼─→ agentgateway :3111 ─→ FastAPI :8000
Antigravity    ─┤     tool allowlist       ├── /mcp            Streamable HTTP, 2026-07-28
web agent      ─┘     (editable from        ├── /agui           AG-UI agent + capabilities
                       the UI)              ├── /listings /filings  REST
                                            └── /observability  audit query + policy API
                                          → stock_market.db + observability.db
```

One backend process, still behind the gateway. The Python MCP server is no longer a stdio child of the gateway — the gateway targets `/mcp` over HTTP.

**The gateway is a product requirement, not plumbing.** It is the single chokepoint every consumer passes through, which is the only reason a tool call made inside a Claude Desktop chat can appear in the same audit view as one made from the web UI. Do not remove it, do not let any host bypass it, and do not "optimize away" the web agent's hop out to `:3111` and back — that hop is what puts the web UI's own calls in the shared log.

## 4. Commands

Cross-platform: every command below is the same on macOS, Linux and Windows. The Windows-only
`run_all.bat`, `setup.ps1` and `run.ps1` were deleted — `scripts/dev.py` replaces all three.

```bash
python3 scripts/dev.py all
```

```bash
python3 scripts/dev.py seed
```

```bash
python3 scripts/get_gateway.py
```

```bash
python3 scripts/mcp_probe.py --as claude-desktop
```

`mcp_probe.py` connects as an MCP client and prints the capability surface. It is
the fastest way to see the gateway's behaviour (run it against `:3111` and then
`--url http://127.0.0.1:8000/mcp` and compare), and `--as` drives audit
attribution without needing a real host installed.

Windows has a one-shot installer and launcher wrapping the same scripts:

```bat
install.bat
```

```bat
run.bat
```

Tests and lint run **from `backend/`** — that is where the pytest and ruff configuration lives, and
neither tool finds it from the repository root. The venv interpreter is `.venv/Scripts/python` on
Windows, `.venv/bin/python` elsewhere.

```bash
cd backend && .venv/bin/python -m pytest
```

```bash
cd backend && .venv/bin/ruff check .
```

The default run is hermetic — no gateway, no credentials, no network. Opt into the rest:

```bash
cd backend && .venv/bin/python -m pytest -m gateway
```

```bash
cd backend && .venv/bin/python -m pytest -m llm
```

Python floor is **3.11** (the code uses `BaseExceptionGroup`); the MCP SDK itself allows 3.10.

## 5. The extensibility contract

`core/registry.py` is the heart of the project. A **module** is a package under `backend/modules/` exposing one `MODULE = ModuleSpec(...)`:

| Field | Purpose |
| :--- | :--- |
| `router` | FastAPI `APIRouter`, auto-mounted on the app |
| `register_tools` | hook called with the MCP server → registers tools |
| `register_resources` | hook called with the MCP server → registers resources |
| `register_prompts` | hook called with the MCP server → registers prompts |
| `seed` | hook that inserts synthetic rows |
| `priority` | lower runs first (router order + seed dependencies) |

`discover_modules()` auto-imports every package, collects its spec, and sorts by `(priority, name)` — the ordering that makes `tools/list` deterministic. **Dropping a directory in `modules/` wires it into REST, MCP and the seeder with no other file edited**, and `tests/test_registry.py` proves it by creating a module at test time. Even `observability` is an ordinary module; infrastructure gets no exemption.

Two ways to declare a tool:

- **Declarative** (`core/api_tools.py` `DataTool`) — a typed function over `core.data`, registered with uniform `{"error": ...}` handling. Used by `listings` and `filings`.
- **Hand-written** `@mcp.tool()` functions — computation with no backing table. Used by `analytics`.

Sync (`def`) tools run on a worker thread, which is why the blocking SQLAlchemy calls never occupy the event loop. Make a tool `async` only when it needs to await something — `compare_companies` does, because it reports progress.

> Tool generation used to `exec()` a generated source string. It does not any more, and `tests/test_tools.py::test_no_exec_anywhere_in_the_backend` parses the AST to keep it that way.

## 6. Current surface

**Tools (11)** — `get_company`, `search_companies`, `list_sectors`, `get_filings`, `get_latest_filing`, `calc_financial_ratios`, `calc_revenue_growth`, `compare_companies`, `sector_ranking`, `list_market_resources`, `read_market_resource`.

**Resources (5)** — `market://companies`, `market://sectors`, `market://companies/{symbol}`, `market://filings/{symbol}/latest`, `market://filings/{symbol}/{period}`.

**Prompts (2)** — `analyze-equity`, `compare-stocks`.

The last two tools exist because the gateway does not proxy resources or prompts (see §9). They are
the governed path to the same data; the native resource surface stays registered and tested.

### 6.1 Caller identities

Under 2026-07-28, `io.modelcontextprotocol/clientInfo` arrives in `_meta` on **every** request, so each call self-identifies — this is what makes per-call source attribution possible at all. Fill this table with **observed** values once the hosts are installed; do not guess, and do not ship a mapping based on a vendor's documentation alone.

| Consumer | Connects via | Observed `clientInfo.name` | Attribution method |
| :--- | :--- | :--- | :--- |
| Claude Code | `.mcp.json`, `type: http` → `:3111/mcp` | _TBD_ | clientInfo |
| VS Code Copilot | `.vscode/mcp.json`, `type: http` | _TBD_ | clientInfo |
| Claude Desktop | `mcp-remote` bridge | _TBD_ | clientInfo, else dedicated route |
| Antigravity | `mcp-remote` bridge | _TBD_ | clientInfo, else dedicated route |
| This repo's web agent | `MCPToolClient` → `:3111/mcp` | set explicitly by us | clientInfo |

Open risk: the `mcp-remote` bridge may rewrite or omit `clientInfo`. If it does, the two bridged hosts get their own gateway route and are attributed by route instead. Never infer a source — an unattributed call is logged `source=unknown`.

## 8. SDLC — how work gets done here

### 8.1 Flow

```
Issue → Spec (SPECS.md) → Branch → Tests first → Implement → Self-review → PR → CI green → Merge → Update docs
```

1. **Issue.** One behavioural change per issue. Link the `SPECS.md` section it satisfies; if none exists, write it first.
2. **Spec.** Every feature gets an entry in `SPECS.md` with acceptance criteria written as assertions, not adjectives. "Fast" is not a criterion; "`tools/list` p95 < 50 ms warm" is.
3. **Branch.** `feat/…`, `fix/…`, `chore/…`, `docs/…`. One phase of the migration per branch.
4. **Tests first.** New tool → a test that calls it and asserts the shape. New protocol behaviour → a conformance assertion. A PR that changes behaviour with no test change gets bounced.
5. **Implement.** Match the surrounding style. New modules follow §5 — if you had to edit a shared file to add a module, the registry contract is broken; fix the registry, not the module.
6. **Self-review.** Run the checklist in §8.3.
7. **PR.** Body states: what changed, which spec section, which invariant (§2) it could plausibly break and why it doesn't.
8. **Docs.** A PR that changes architecture, commands, or the tool surface updates `CLAUDE.md` in the same commit.

### 8.2 Definition of done

- [ ] Acceptance criteria in `SPECS.md` all pass
- [ ] Tests added and green; `pytest` green on a clean clone
- [ ] `ruff check` clean
- [ ] No new `exec`, no stdout writes, no fabricated UI values
- [ ] Invariants §2 hold
- [ ] `CLAUDE.md` / `SPECS.md` / `DESIGN.md` updated if the change touched what they describe
- [ ] Checklist box in §7 ticked

### 8.3 Self-review checklist

- Does this change any seeded value? (If yes: stop, it must be deliberate and documented.)
- Does it log to stdout anywhere?
- Does it add a UI signal the backend does not actually produce?
- Does it require editing a shared file to add a module?
- Does it hardcode a Windows path or a `.exe`?
- Does it introduce a shared mutable session across concurrent requests?
- Does it claim a protocol behaviour without a conformance assertion?

### 8.4 Adding a new module — the 5-minute path

1. `mkdir backend/modules/<name>/`
2. `models.py`, `schemas.py`, `repository.py`, `router.py`, `seed.py`, `tools.py`
3. `__init__.py` exports `MODULE = ModuleSpec(name=…, router=…, register_tools=…, seed=…)`
4. `python -m core.seed --reset`
5. Add a golden test for each new tool

Nothing else is edited. If it is, that's a bug in the registry.

### 8.5 Adding a tool to an existing module

- Pure data proxy → append an `EndpointTool` row in that module's `tools.py`.
- Computation → add an `@mcp.tool()` async function, put the maths in `core/calculations.py` as a pure function, and unit-test the pure function separately.

Both cases: add the tool to the golden snapshot and give it a `TOOL_LABEL` + a card in `frontend/components/chat/toolCards.tsx` if it should render as a card.

## 9. Traps already paid for

Learned by testing, not assumed. Keep this list — it is the expensive part of the repo.

- **agentgateway 1.4.1 does not proxy resources or prompts.** Measured against the real binary: `tools/*` passes through faithfully, but `resources/list`, `resources/templates/list` and `prompts/list` all come back as empty arrays, and `ttlMs`/`cacheScope` are rewritten to `0`/`private` on list results. Since every consumer goes through the gateway, the native resource surface is unreachable in practice — hence the `read_market_resource` tool. Re-test on each gateway upgrade; if it starts proxying them, the bridge tools can be retired.
- **agentgateway is HTTP/SSE-only.** It cannot be spawned as a stdio child. This is why Claude Desktop and Antigravity go through the `mcp-remote` bridge while Claude Code and VS Code use `type: http` directly.
- **SDK v2 serves the legacy handshake whether you want it or not.** `MCPServer` answers both 2026-07-28 and the 2025-11-25 `initialize` handshake from one endpoint, with no switch to disable it. `ProtocolGuardMiddleware` (`app/middleware.py`) is what actually enforces the single-revision policy; `STRICT_PROTOCOL=false` turns it off.
- **`BaseHTTPMiddleware` cannot sit in front of the MCP app.** `@app.middleware("http")` buffers the request/response cycle and raises `RuntimeError: No response returned.` against the streaming endpoint. Both middlewares here are pure ASGI for that reason.
- **An ASGI middleware that buffers the body must delegate `receive` afterwards.** Returning a synthetic `http.disconnect` once the body is consumed makes the transport think the client vanished, and it abandons the request without sending a response.
- **A `-> list[dict]` return annotation breaks the error path.** The SDK derives an output schema from the annotation and validates against it, so a tool returning `{"error": ...}` fails validation and surfaces as `isError`. List-returning tools are annotated `list[dict] | dict`.
- **`Origin`/`Host` validation must wildcard the port.** The gateway forwards with its own `Host` (`127.0.0.1:3111`), so a host list pinned to `:8000` answers `421 Misdirected Request` to every proxied call.
- **Missing prompt arguments surface as `-32603`, not `-32602`.** The SDK validates prompt arguments before the handler runs and reports the failure as Internal error. The spec calls for Invalid params. Recorded in SPECS PROMPT-1.3 rather than papered over.
- **Retrying the Streamable HTTP connect crashes on teardown** (v1 SDK): its anyio task group assumes one connect attempt, so `session.py` probes the raw TCP port first instead of retrying the handshake. Re-verify this under SDK v2 before deleting `_wait_for_port`.
- **agentgateway has no log viewer or logs API.** `/gateway-logs` tails its stdout/stderr files instead. Its web-UI "MCP" section is a wizard that creates a *new* target rather than editing the existing one — it once created a stray target on a dead port.
- **Audit persistence is ours, not the gateway's.** Rather than depending on a `database:` key that failed validation on the older build, the backend records every call itself in an ASGI middleware (`modules/observability/recorder.py`) into `observability.db`. It survives restarts of either process and is queryable by the UI. The gateway log ingester exists only for calls the gateway *refused*, which never reach the backend.
- **Version floor: agentgateway ≥ 1.4.1.** 1.4 (2026-07-27) added 2026-07-28 support; 1.4.1 added compatibility fixes. Anything older cannot front a 2026-07-28 server.
- **`mcp.session.id` is a dead log field** under this revision — sessions were removed from the transport. Correlate on `clientInfo` + `traceparent` instead.
- **`policies.cors` in the gateway config only affects browser callers.** Native clients send no preflight, so it has zero effect on whether the 5 consumers connect.
- **A host that "stops logging" may just have a reverted config.** `claude_desktop_config.json` silently reset itself to a direct stdio entry once, routing around the gateway entirely — tools kept working, invisibly. Check the host config before blaming the server.
- **Tool-call ids are not unique across a conversation.** Some proxies emit turn-scoped ids that reset each turn, so `ObservabilityRail.tsx` builds a synthetic React key from message id + position.
- **Flex and grid children default to `min-height: auto`.** They refuse to shrink below their content, so a scroll container nested inside one grows to fit instead of scrolling and everything past the fold is clipped by an ancestor's `overflow: hidden` — with no page scroll to fall back on. Every layout child in `globals.css` sets `min-height: 0` for this reason. This broke chat scrolling once already.
- **React state updaters must stay pure.** Writing `localStorage` inside a `setState` updater made a toggle silently do nothing, because React may defer or double-invoke updaters. Two separate bugs in this repo had that shape; compute the next value in the handler instead.
- **`from core.config import settings` captures the singleton at import.** The test harness rebinds it, so a security flag read that way was decided by a stale object. `modules/observability/policy.py` imports the module and reads `config.settings` instead.
- **CORS `allow_methods` is a real gate.** The allowlist editor's `PUT` failed its preflight and surfaced only as "Failed to fetch" in the browser — invisible in a diff, obvious on the first click.
- **Reasoning models stream `delta.reasoning_content` separately.** It is deliberately not forwarded to the UI — only `delta.content` is. Never surface chain-of-thought.
