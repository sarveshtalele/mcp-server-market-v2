# mcp-server-market

A synthetic stock-exchange dataset served over **MCP 2026-07-28**, behind **agentgateway**, with a
Control Room web UI that shows every MCP call from every consumer in one place.

Five consumers — Claude Desktop, Claude Code, VS Code Copilot, Antigravity and this repo's own web
chat — all reach the server through one gateway. That is what makes a tool call made inside a
Claude Desktop conversation show up in the same audit view as one made from the browser.

> The data is generated by `Faker` with a fixed seed. It is **not** real market data and must never
> be presented as such.

```
Claude Desktop ─┐
Claude Code    ─┤
VS Code Copilot─┼─→ agentgateway :3111 ─→ FastAPI :8000 ─→ SQLite
Antigravity    ─┤    allowlist            ├── /mcp            MCP 2026-07-28, Streamable HTTP
web chat :3000 ─┘    audit + caller       ├── /agui           AG-UI stream for the UI
                     attribution          ├── /listings /filings   REST
                                          └── /observability  audit query API
```

## 1. Requirements

| | Version | Notes |
| :--- | :--- | :--- |
| Python | **3.11+** | The code uses `BaseExceptionGroup` (a 3.11 builtin). The MCP SDK itself allows 3.10. |
| Node.js | 18+ | Only needed for the web UI. |
| agentgateway | **1.4.1+** | 1.4 (2026-07-27) added MCP 2026-07-28 support; 1.4.1 added compatibility fixes. Older builds cannot front this server. |
| OS | macOS (Apple Silicon), Linux (x86_64/arm64), Windows (x86_64) | agentgateway publishes binaries for exactly these. |

An LLM key is optional: the MCP server, the REST API and the audit log all run without one. Only
the web chat needs a model.

## 2. Install

### 2.0 Windows: one command

```bat
install.bat
```

That checks your Python version, creates the virtualenv, installs backend and
frontend dependencies, downloads and verifies agentgateway, seeds the dataset and
writes both `.env` files. Then:

```bat
run.bat
```

`run.bat` also takes a target: `run.bat backend`, `run.bat gateway`,
`run.bat frontend`, `run.bat seed`.

macOS and Linux users, and anyone who wants to see each step, follow 2.1–2.4.

### 2.1 Backend

```bash
python -m venv backend/.venv
```

macOS / Linux:

```bash
backend/.venv/bin/pip install -r backend/requirements-dev.txt
```

Windows (PowerShell):

```powershell
backend\.venv\Scripts\pip install -r backend\requirements-dev.txt
```

### 2.2 Build the dataset

```bash
python scripts/dev.py seed
```

Deterministic: the same rows on every machine, every time. Re-running it is safe — it rebuilds the
market database and leaves the audit log alone (they are separate files on purpose).

### 2.3 Install agentgateway

One command, any supported OS. It picks the right release asset for your machine, verifies the
published SHA-256, and installs into `backend/mcp_server/gateway/bin/` (gitignored — the binary is
~80 MB and is never committed):

```bash
python scripts/get_gateway.py
```

Pin a different version if you need to:

```bash
python scripts/get_gateway.py --version v1.4.1 --force
```

<details>
<summary>Manual install, if you would rather not run the script</summary>

1. Download the asset for your platform from
   <https://github.com/agentgateway/agentgateway/releases/tag/v1.4.1>:

   | Platform | Asset |
   | :--- | :--- |
   | macOS (Apple Silicon) | `agentgateway-darwin-arm64` |
   | Linux x86_64 | `agentgateway-linux-amd64` |
   | Linux arm64 | `agentgateway-linux-arm64` |
   | Windows x86_64 | `agentgateway-windows-amd64.exe` |

2. Put it at `backend/mcp_server/gateway/bin/agentgateway` (`agentgateway.exe` on Windows).
3. On macOS/Linux make it executable: `chmod +x backend/mcp_server/gateway/bin/agentgateway`.
4. On macOS, Gatekeeper may block an unsigned download. Either right-click → Open once, or:
   `xattr -d com.apple.quarantine backend/mcp_server/gateway/bin/agentgateway`.
5. Check it: `backend/mcp_server/gateway/bin/agentgateway --version` → `"version": "1.4.1"`.

</details>

### 2.4 LLM credentials (optional — only the web chat needs them)

```bash
cp backend/.env.example backend/.env
```

Windows:

```bat
copy backend\.env.example backend\.env
```

Then set two values in `backend/.env`:

| Variable | What it is |
| :--- | :--- |
| `LLM_API_KEY` | Your key. Required for the chat; everything else runs without it. |
| `LLM_BASE_URL` | The **root** of an OpenAI-compatible endpoint, **without** `/v1` — the code appends it. Leave blank to use OpenAI directly. |
| `LLM_MODEL` | Model id as your endpoint names it. |
| `MAX_TOKENS` | Response cap. The default 4096 is generous enough for reasoning models. |

**OpenAI directly**

```ini
LLM_API_KEY=sk-...
LLM_BASE_URL=
LLM_MODEL=gpt-4.1
```

**A LiteLLM proxy** (what this project was built against)

```ini
LLM_API_KEY=sk-litellm-...
LLM_BASE_URL=https://litellm-proxy.example.net
LLM_MODEL=claude-sonnet-4-6
```

**Anthropic through an OpenAI-compatible gateway**

```ini
LLM_API_KEY=...
LLM_BASE_URL=https://your-gateway.example.net
LLM_MODEL=claude-sonnet-4-6
```

Common mistakes: including `/v1` in `LLM_BASE_URL` (it gets appended, so you end up
with `/v1/v1`), and naming a model your endpoint does not expose — the chat then
fails with the provider's error, which the UI shows verbatim rather than hiding.

The variables use an `LLM_` prefix on purpose, so they cannot collide with any
`OPENAI_*` or `ANTHROPIC_*` values already in your shell environment.

Restart the backend after editing `.env`. Check it took:

```bash
curl http://127.0.0.1:8000/health
```

If `LLM_API_KEY` is unset, the chat replies with a clear message saying so, and the
MCP server, REST API and audit log keep working normally.

## 3. Run

Everything, in the right order, on any OS:

```bash
python scripts/dev.py all
```

That starts the gateway on `:3111`, waits for the backend on `:8000` to report healthy, then starts
the UI on `:3000`. Ctrl+C stops all three.

Individually:

```bash
python scripts/dev.py gateway
```

```bash
python scripts/dev.py backend
```

```bash
python scripts/dev.py frontend
```

| Where | What |
| :--- | :--- |
| <http://localhost:3000> | Control Room — chat, MCP Servers, Audit Log |
| <http://127.0.0.1:8000/docs> | REST API reference |
| <http://127.0.0.1:8000/observability/calls> | Audit log as JSON |
| <http://127.0.0.1:3111/mcp> | The MCP endpoint every host connects to |

### How the gateway is configured

`backend/mcp_server/gateway/config.yaml` holds two things that matter:

- **The target.** The gateway forwards to `http://127.0.0.1:8000/mcp` over Streamable HTTP. It used
  to spawn the Python server as a stdio child, which meant the config carried absolute interpreter
  paths and only worked on one machine.
- **The allowlist.** `policies.mcpAuthorization` lists every callable tool. Adding a tool to the
  server does **not** make it callable until it is listed here — that is the governance surface, and
  the MCP Servers page flags it when the two fall out of sync.

## 4. Connect an AI host

Every host points at the **gateway** on `:3111`, never at the backend's `:8000/mcp`. A host wired
straight to the backend still works — and disappears from the audit log, which defeats the point of
the whole setup.

Start the stack first (`python scripts/dev.py all`, or `run.bat` on Windows). The gateway must be
running before a host connects.

### 4.1 Claude Code

Already configured: the repo ships [.mcp.json](.mcp.json).

```json
{
  "mcpServers": {
    "stock-exchange": {
      "type": "http",
      "url": "http://127.0.0.1:3111/mcp"
    }
  }
}
```

Open Claude Code in this directory and approve the server when prompted. Verify with `/mcp` — you
should see `stock-exchange` connected with 11 tools. To use it from another project, copy that block
into that project's `.mcp.json`, or register it globally:

```bash
claude mcp add --transport http stock-exchange http://127.0.0.1:3111/mcp
```

### 4.2 VS Code (GitHub Copilot, agent mode)

Already configured: the repo ships [.vscode/mcp.json](.vscode/mcp.json).

```json
{
  "servers": {
    "stock-exchange": {
      "type": "http",
      "url": "http://127.0.0.1:3111/mcp"
    }
  }
}
```

Open the folder in VS Code, then Copilot Chat → **Agent** mode → the tools icon. `stock-exchange`
appears in the tool picker. VS Code 1.99+ is required for `type: http`. For every workspace instead
of just this one, put the same block in your user `settings.json` under `"mcp"`.

### 4.3 Claude Desktop

Claude Desktop's config file does not accept a plain remote `type: http` entry, so it reaches the
gateway through the `mcp-remote` bridge. That needs **Node.js on PATH** (`npx` must resolve).

Config file location:

| OS | Path |
| :--- | :--- |
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

Merge in the contents of [claude_desktop_config.example.json](claude_desktop_config.example.json):

```json
{
  "mcpServers": {
    "stock-exchange": {
      "command": "npx",
      "args": ["mcp-remote", "http://127.0.0.1:3111/mcp"]
    }
  }
}
```

Then **fully quit and relaunch** Claude Desktop — closing the window is not enough; the config is
only read at process start. Verify from the tools icon in the composer.

> Watch for this: Claude Desktop's own connector UI has been observed silently rewriting
> `claude_desktop_config.json` back to a direct entry. Tools keep working, but the calls stop
> appearing in the Audit Log. If a host goes quiet in the log, check its config file before
> suspecting the server.

### 4.4 Antigravity

Settings → MCP → Add server, or paste into its `mcp_config.json`. Same bridge as Claude Desktop —
see [integrations/antigravity.mcp.example.json](integrations/antigravity.mcp.example.json):

```json
{
  "mcpServers": {
    "stock-exchange": {
      "command": "npx",
      "args": ["mcp-remote", "http://127.0.0.1:3111/mcp"]
    }
  }
}
```

### 4.5 Cursor, Windsurf, or any other MCP client

Anything that speaks Streamable HTTP connects with the same URL:

```
http://127.0.0.1:3111/mcp
```

For Cursor, that is `.cursor/mcp.json` in the project or `~/.cursor/mcp.json` globally, using the
same `type: http` shape as Claude Code. For a client that only supports stdio, wrap it in
`npx mcp-remote http://127.0.0.1:3111/mcp` as Claude Desktop does.

### 4.6 Confirm it worked

Open **MCP Servers** in the Control Room (<http://localhost:3000/servers>). Your host appears under
*Callers seen* with the `clientInfo` name it reported. Then run a tool from that host and watch the
row arrive in **Audit Log** and in the **Fleet Activity** panel on the chat page.

If the host shows up as `unknown`, it did not send a usable
`io.modelcontextprotocol/clientInfo` — most likely the `mcp-remote` bridge dropped it. The fix is a
dedicated gateway listener for that host so the route becomes the identity; see
`MIGRATION_PLAN.md` decision D-1b. The source is never guessed.

## 5. What the server exposes

**11 tools** — `get_company`, `search_companies`, `list_sectors`, `get_filings`,
`get_latest_filing`, `calc_financial_ratios`, `calc_revenue_growth`, `compare_companies`,
`sector_ranking`, plus `list_market_resources` and `read_market_resource` (see the gateway note
below).

**5 resources** — `market://companies`, `market://sectors`, `market://companies/{symbol}`,
`market://filings/{symbol}/latest`, `market://filings/{symbol}/{period}`.

**2 prompts** — `analyze-equity`, `compare-stocks`.

> **Gateway note (measured, not assumed).** agentgateway 1.4.1 proxies `tools/*` faithfully but
> answers `resources/list`, `resources/templates/list` and `prompts/list` with empty arrays, and
> rewrites `ttlMs` to 0 / `cacheScope` to `private` on list results. Since every consumer goes
> through the gateway, the native resource and prompt surface is currently only reachable by a
> client talking to the backend directly. `read_market_resource(uri)` is the governed path to the
> same data — it is an ordinary tool, so it passes through and stays audited. The MCP Servers page
> shows *declared* and *via gateway* counts side by side rather than pretending they agree.

## 6. Observability

Every MCP request that reaches the server is recorded with: timestamp, source, caller name and
version, method, tool or resource name, a truncated argument preview, status, error code, latency,
protocol version and trace id.

- **Fleet Activity** (right rail, chat page) — live cross-host feed over SSE.
- **Audit Log** — filterable history with per-row inspection and a summary strip.
- **MCP Servers** — gateway status, allowlist, capability surface, callers seen in the last hour.

**Attribution** comes from `io.modelcontextprotocol/clientInfo`. A caller that sends nothing usable
is recorded as `unknown` — never guessed. Override the mapping without touching code:

```bash
MCP_SOURCE_PATTERNS='{"my-host":"my-label"}'
```

**Conversation attribution is partial by design.** MCP defines no conversation identifier in any
revision, so external hosts cannot supply one; those rows show `n/a`. This repo's own client injects
its conversation id via the W3C `baggage` key, so Control Room rows link back to the exact chat.
Calls with no identifier are grouped into **episodes** by idle gap — a reading aid inferred from
timing, never presented as a conversation.

### Adding a module

Drop a package under `backend/modules/` exporting one `MODULE = ModuleSpec(...)` and it is wired
into REST, MCP and the seeder with **no other file edited**. `tests/test_registry.py` enforces that
by creating a module at test time and asserting it appears. If you ever have to edit a shared file
to add a module, that is a bug in the registry, not in your module.

## 8. Troubleshooting

| Symptom | Cause |
| :--- | :--- |
| `Cannot reach the MCP server at http://127.0.0.1:3111/mcp` | The gateway is not running. `python scripts/dev.py gateway`. |
| Chat replies "LLM_API_KEY is not set" | Expected without credentials. Everything except the chat still works. |
| Audit Log is empty | Nothing has called the server yet, or a host is wired directly to `:8000` and bypassing the gateway. |
| `421 Misdirected Request` on `/mcp` | The `Host` header is not a loopback address. The endpoint binds to localhost and validates `Origin`/`Host` — mandatory for this transport. |
| Host connects but resources and prompts are missing | The gateway does not proxy them; use `read_market_resource`. See §5. |
| `-32022 Unsupported protocol version` | Something is speaking an older MCP revision. This server is 2026-07-28 only; set `STRICT_PROTOCOL=false` to also accept the legacy handshake. |
| macOS: "cannot be opened because the developer cannot be verified" | Gatekeeper quarantined the gateway binary. See §2.3. |
