# mcp-server-market

A synthetic stock-exchange dataset served over **MCP 2026-07-28**, behind **agentgateway**, with a
Control Room web UI that shows every MCP call from every consumer in one place.

Five consumers — Claude Desktop, Claude Code, VS Code Copilot, Antigravity and this repo's own web
chat — all reach the server through one gateway. That is what makes a tool call made inside a
Claude Desktop conversation show up in the same audit view as one made from the browser.

> The data is generated by `Faker` with a fixed seed. It is **not** real market data and must never
> be presented as such.

```
Claude Desktop ─┐
Claude Code    ─┤
VS Code Copilot─┼─→ agentgateway :3111 ─→ FastAPI :8000 ─→ SQLite
Antigravity    ─┤    allowlist            ├── /mcp            MCP 2026-07-28, Streamable HTTP
web chat :3000 ─┘    audit + caller       ├── /agui           AG-UI stream for the UI
                     attribution          ├── /listings /filings   REST
                                          └── /observability  audit query API
```

## 1. Requirements

| | Version | Notes |
| :--- | :--- | :--- |
| Python | **3.11+** | The code uses `BaseExceptionGroup` (a 3.11 builtin). The MCP SDK itself allows 3.10. |
| Node.js | 18+ | Only needed for the web UI. |
| agentgateway | **1.4.1+** | 1.4 (2026-07-27) added MCP 2026-07-28 support; 1.4.1 added compatibility fixes. Older builds cannot front this server. |
| OS | macOS (Apple Silicon), Linux (x86_64/arm64), Windows (x86_64) | agentgateway publishes binaries for exactly these. |

An LLM key is optional: the MCP server, the REST API and the audit log all run without one. Only
the web chat needs a model.

## 2. Install

### 2.0 Windows: one command

**Clone the repository — do not copy the folder from another machine.**

```bat
git clone https://github.com/sarveshtalele/mcp-server-market-v2.git
cd mcp-server-market-v2
install.bat
```

Then start everything:

```bat
run.bat
```

`run.bat` also takes a target: `run.bat backend`, `run.bat gateway`,
`run.bat frontend`, `run.bat seed`.

#### What install.bat does

Seven steps: checks Python is 3.11+, creates `backend\.venv`, installs the backend
dependencies, downloads the **Windows** agentgateway build and verifies its
published SHA-256, seeds the synthetic dataset, writes `backend\.env` and
`frontend\.env.local` from the examples, and installs the frontend dependencies.

It never overwrites an existing `.env`, so re-running it is safe.

If npm is missing the install still succeeds — you get the MCP server, the REST
API and the audit log, just no browser UI.

#### Prerequisites it does not install for you

| Need | Notes |
| :--- | :--- |
| **Python 3.11+** | <https://www.python.org/downloads/> — tick *Add python.exe to PATH* during setup |
| **Node.js 18+** | <https://nodejs.org/> — only for the Control Room web UI, and for the `mcp-remote` bridge that Claude Desktop and Antigravity use |
| **git** | To clone |

#### Why clone rather than copy the folder

A working checkout is ~3 MB in git but around 545 MB on disk. The difference is
machine-specific and must not travel between systems:

| Not in the repo | Size | Why copying it breaks |
| :--- | :--- | :--- |
| `backend\.venv` | ~166 MB | Absolute paths and platform binaries are baked in; a macOS or Linux venv cannot run on Windows |
| `frontend\node_modules` | ~256 MB | Native modules are compiled per OS and architecture |
| `backend\mcp_server\gateway\bin` | ~81 MB | The gateway binary is per-platform — a macOS build will not execute on Windows |
| `backend\*.db` | ~220 KB | Regenerated deterministically by the seeder |
| `backend\.env` | — | Your LLM credentials; gitignored on purpose |
| `frontend\.next` | ~49 MB | Build output |

All of it is gitignored, and `install.bat` rebuilds each piece for the machine it
runs on.

> **Caveat, stated plainly.** `install.bat` and `run.bat` were written for Windows
> and are syntax-checked (plain ASCII, verified programmatically — a stray em dash
> in a `.ps1` broke this project's parser once before), but they have only ever
> been *executed* on macOS. Your first Windows run is genuinely their first run.
> If a step fails, the script stops and names which of the seven it was, and the
> equivalent manual steps are in 2.1–2.4 below.

macOS and Linux users, and anyone who wants to see each step, follow 2.1–2.4.

### 2.1 Backend

```bash

```

Deterministic: the same rows on every machine, every time. Re-running it is safe — it rebuilds the

### 2.3 Install agentgateway

One command, any supported OS. It picks the right release asset for your machine, verifies the
published SHA-256, and installs into `backend/mcp_server/gateway/bin/` (gitignored — the binary is
~80 MB and is never committed):

```bash
python3 scripts/get_gateway.py
```

Pin a different version if you need to:

```bash
python3 scripts/get_gateway.py --version v1.4.1 --force
```

1. Download the asset for your platform from

### 2.4 LLM credentials (optional — only the web chat needs them)

```bash
cp backend/.env.example backend/.env
```

Windows:

```bat
copy backend\.env.example backend\.env
```

Then set two values in `backend/.env`:

| Variable | What it is |
| :--- | :--- |
| `LLM_API_KEY` | Your key. Required for the chat; everything else runs without it. |
| `LLM_BASE_URL` | The **root** of an OpenAI-compatible endpoint, **without** `/v1` — the code appends it. Leave blank to use OpenAI directly. |
| `LLM_MODEL` | Model id as your endpoint names it. |
| `MAX_TOKENS` | Response cap. The default 4096 is generous enough for reasoning models. |

**OpenAI directly**

```ini
LLM_API_KEY=sk-...
LLM_BASE_URL=
LLM_MODEL=gpt-4.1
```

**A LiteLLM proxy** (what this project was built against)

```ini
LLM_API_KEY=sk-litellm-...
LLM_BASE_URL=https://litellm-proxy.example.net
LLM_MODEL=claude-sonnet-4-6
```

**Anthropic through an OpenAI-compatible gateway**

```ini
LLM_API_KEY=...
LLM_BASE_URL=https://your-gateway.example.net
LLM_MODEL=claude-sonnet-4-6
```

Common mistakes: including `/v1` in `LLM_BASE_URL` (it gets appended, so you end up
with `/v1/v1`), and naming a model your endpoint does not expose — the chat then
fails with the provider's error, which the UI shows verbatim rather than hiding.

The variables use an `LLM_` prefix on purpose, so they cannot collide with any
`OPENAI_*` or `ANTHROPIC_*` values already in your shell environment.

Restart the backend after editing `.env`. Check it took:

```bash
curl http://127.0.0.1:8000/health
```

If `LLM_API_KEY` is unset, the chat replies with a clear message saying so, and the
MCP server, REST API and audit log keep working normally.

Everything, in the right order, on any OS:

```bash
python3 scripts/dev.py all
```

That starts the gateway on `:3111`, waits for the backend on `:8000` to report healthy, then starts
the UI on `:3000`. Ctrl+C stops all three.

Individually:

```bash
python3 scripts/dev.py gateway
```

```bash
python3 scripts/dev.py backend
```

```bash
python3 scripts/dev.py frontend
```

| Where | What |
| :--- | :--- |
| <http://localhost:3000> | Control Room — chat, MCP Servers, Audit Log |
| <http://127.0.0.1:8000/docs> | REST API reference |
| <http://127.0.0.1:8000/observability/calls> | Audit log as JSON |
| <http://127.0.0.1:3111/mcp> | The MCP endpoint every host connects to |

### How the gateway is configured

`backend/mcp_server/gateway/config.yaml` holds two things that matter:

- **The target.** The gateway forwards to `http://127.0.0.1:8000/mcp` over Streamable HTTP. It used
  to spawn the Python server as a stdio child, which meant the config carried absolute interpreter
  paths and only worked on one machine.
- **The allowlist.** `policies.mcpAuthorization` lists every callable tool. Adding a tool to the
  server does **not** make it callable until it is listed here — that is the governance surface, and
  the MCP Servers page flags it when the two fall out of sync.

## 4. Connect an AI host

Every host points at the **gateway** on `:3111`, never at the backend's `:8000/mcp`. A host wired
straight to the backend still works — and disappears from the audit log, which defeats the point of
the whole setup.

Start the stack first (`python3 scripts/dev.py all`, or `run.bat` on Windows). The gateway must be
running before a host connects.

### 4.1 Claude Code

Already configured: the repo ships [.mcp.json](.mcp.json).

```json
{
  "mcpServers": {
    "mcp-market-mcp-server": {
      "type": "http",
      "url": "http://127.0.0.1:3111/mcp"
    }
  }
}
```

Open Claude Code in this directory and approve the server when prompted. Verify with `/mcp` — you
should see `mcp-market-mcp-server` connected with 11 tools. To use it from another project, copy that block
into that project's `.mcp.json`, or register it globally:

```bash
claude mcp add --transport http mcp-market-mcp-server http://127.0.0.1:3111/mcp
```

### 4.2 VS Code (GitHub Copilot, agent mode)

Already configured: the repo ships [.vscode/mcp.json](.vscode/mcp.json).

```json
{
  "servers": {
    "mcp-market-mcp-server": {
      "type": "http",
      "url": "http://127.0.0.1:3111/mcp"
    }
  }
}
```

Open the folder in VS Code, then Copilot Chat → **Agent** mode → the tools icon. `mcp-market-mcp-server`
appears in the tool picker. VS Code 1.99+ is required for `type: http`. For every workspace instead
of just this one, put the same block in your user `settings.json` under `"mcp"`.

### 4.3 Claude Desktop

Claude Desktop's config file does not accept a plain remote `type: http` entry, so it reaches the
gateway through the `mcp-remote` bridge. That needs **Node.js on PATH** (`npx` must resolve).

Config file location:

| OS | Path |
| :--- | :--- |
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |

Merge in the contents of [claude_desktop_config.example.json](claude_desktop_config.example.json):

```json
{
  "mcpServers": {
    "mcp-market-mcp-server": {
      "command": "npx",
      "args": ["mcp-remote", "http://127.0.0.1:3111/mcp"]
    }
  }
}
```

Then **fully quit and relaunch** Claude Desktop — closing the window is not enough; the config is
only read at process start. Verify from the tools icon in the composer.

> Watch for this: Claude Desktop's own connector UI has been observed silently rewriting
> `claude_desktop_config.json` back to a direct entry. Tools keep working, but the calls stop
> appearing in the Audit Log. If a host goes quiet in the log, check its config file before
> suspecting the server.

### 4.4 Antigravity

Settings → MCP → Add server, or paste into its `mcp_config.json`. Same bridge as Claude Desktop —
see [integrations/antigravity.mcp.example.json](integrations/antigravity.mcp.example.json):

```json
{
  "mcpServers": {
    "mcp-market-mcp-server": {
      "command": "npx",
      "args": ["mcp-remote", "http://127.0.0.1:3111/mcp"]
    }
  }
}
```

### 4.5 Cursor, Windsurf, or any other MCP client

Anything that speaks Streamable HTTP connects with the same URL:

```
http://127.0.0.1:3111/mcp
```

For Cursor, that is `.cursor/mcp.json` in the project or `~/.cursor/mcp.json` globally, using the
same `type: http` shape as Claude Code. For a client that only supports stdio, wrap it in
`npx mcp-remote http://127.0.0.1:3111/mcp` as Claude Desktop does.

### 4.6 Confirm it worked

Open **MCP Servers** in the Control Room (<http://localhost:3000/servers>). Your host appears under
*Callers seen* with the `clientInfo` name it reported. Then run a tool from that host and watch the
row arrive in **Audit Log** and in the **Fleet Activity** panel on the chat page.

If the host shows up as `unknown`, it did not send a usable
`io.modelcontextprotocol/clientInfo` — most likely the `mcp-remote` bridge dropped it. The fix is a
dedicated gateway listener for that host so the route becomes the identity; see
`MIGRATION_PLAN.md` decision D-1b. The source is never guessed.

## 5. Use it as an MCP client

Wiring a host (§4) makes the tools available. This section is about actually
using them, and about talking to the server from your own code.

### 5.1 Check your connection in one command

```bash
python3 scripts/mcp_probe.py
```

It connects as a client, prints the protocol version, every tool, resource and
prompt, calls `get_company`, and tells you where to see the call in the Audit
Log. Real output through the gateway:

```
connected to      http://127.0.0.1:3111/mcp
identifying as    mcp-probe
protocol version  2026-07-28
server            mcp-market-mcp-server 2.0.0

tools (11):
  get_company
  search_companies
  ...

tools/list cache  ttlMs=0 cacheScope=private resultType=complete

resources (0):

prompts (0):

note: no resources or prompts listed. agentgateway does not
      proxy them — use the read_market_resource tool, which
      passes through and stays audited.
```

Point it at the backend directly and the difference is visible immediately —
this is the gateway limitation from §6, not a broken server:

```bash
python3 scripts/mcp_probe.py --url http://127.0.0.1:8000/mcp
```

```
tools/list cache  ttlMs=3600000 cacheScope=public resultType=complete

resources (2):
  market://companies
  market://sectors
  market://companies/{symbol}
  market://filings/{symbol}/latest
  market://filings/{symbol}/{period}

prompts (2):
  analyze-equity
  compare-stocks
```

Use `--as` to impersonate a host and watch attribution work without installing
anything:

```bash
python3 scripts/mcp_probe.py --as claude-desktop
```

That call shows up in the Audit Log tagged `claude-desktop`. A name the server
does not recognise is recorded as `unknown` rather than guessed — see §7 for how
to extend the mapping.

### 5.2 Using it inside a host

Once connected, just ask. The host decides when to call a tool; you do not
invoke them by name, though naming one usually nudges it:

- *"Show me AAPL's company profile"* → `get_company`
- *"Compare JPM, BAC and WFC on ROE"* → `compare_companies`, possibly
  `calc_financial_ratios`
- *"Which Technology companies are largest by market cap?"* → `sector_ranking`
- *"What's NVDA's revenue trend?"* → `calc_revenue_growth`
- *"Read market://companies/MSFT"* → `read_market_resource`

**Resources and prompts.** In a host connected through the gateway they will not
appear in the attach/prompt menus, because the gateway does not forward them.
Ask for the URI instead and the model will use `read_market_resource`:

> Read `market://filings/AAPL/latest` and summarise the quarter.

The two prompts (`analyze-equity`, `compare-stocks`) are server-declared
workflows. Through the gateway, ask for them in words:

> Run an analyze-equity memo for AAPL.

**Expect it to refuse from memory.** The server ships `instructions` telling
clients to answer only from tool results and to say so when a call fails. If you
ask about a ticker that is not in the synthetic dataset, a well-behaved host will
tell you rather than inventing figures.

### 5.3 The built-in terminal client

The repo ships its own MCP client — useful for testing the server without a
browser or an IDE:

```bash
cd backend && .venv/bin/python -m mcp_client.cli_chat
```

It connects through the gateway, adapts the MCP tools to OpenAI
function-calling, and runs a tool loop in your terminal. It needs `LLM_API_KEY`
in `backend/.env` (§2.4); without it, it exits with
`Set LLM_API_KEY and LLM_BASE_URL in backend/.env.`

### 5.4 Writing your own client

The whole client is about fifteen lines with the official SDK
(`pip install "mcp>=2.0,<3"`):

```python
import asyncio
from mcp import Client, Implementation

async def main():
    async with Client(
        "http://127.0.0.1:3111/mcp",
        client_info=Implementation(name="my-app", version="1.0.0"),
        mode="2026-07-28",
    ) as client:
        tools = await client.list_tools()
        print([t.name for t in tools.tools])

        result = await client.call_tool("get_company", {"symbol": "AAPL"})
        print(result.content[0].text)

asyncio.run(main())
```

Three things worth knowing:

- **`client_info` is your identity.** It travels in `_meta` on every request
  under 2026-07-28 and is what the Audit Log attributes the call to. Pick
  something recognisable.
- **`mode="2026-07-28"` pins the revision.** Left on `"auto"` the SDK would
  happily negotiate an older one; this server only serves 2026-07-28.
- **Point at the gateway**, not `:8000/mcp`. A direct connection works and is
  invisible to the audit log, which defeats the point.

To correlate calls with your own conversations, pass a conversation id — MCP has
no field for one, so the W3C `baggage` key is the reserved slot for exactly this:

```python
await client.call_tool(
    "get_company",
    {"symbol": "AAPL"},
    meta={"baggage": "conversationId=my-thread-1"},
)
```

`scripts/mcp_probe.py` is a longer worked example of all of the above.

## 6. What the server exposes

**11 tools** — `get_company`, `search_companies`, `list_sectors`, `get_filings`,
`get_latest_filing`, `calc_financial_ratios`, `calc_revenue_growth`, `compare_companies`,
`sector_ranking`, plus `list_market_resources` and `read_market_resource` (see the gateway note
below).

**5 resources** — `market://companies`, `market://sectors`, `market://companies/{symbol}`,
`market://filings/{symbol}/latest`, `market://filings/{symbol}/{period}`.

**2 prompts** — `analyze-equity`, `compare-stocks`.

> **Gateway note (measured, not assumed).** agentgateway 1.4.1 proxies `tools/*` faithfully but
> answers `resources/list`, `resources/templates/list` and `prompts/list` with empty arrays, and
> rewrites `ttlMs` to 0 / `cacheScope` to `private` on list results. Since every consumer goes
> through the gateway, the native resource and prompt surface is currently only reachable by a
> client talking to the backend directly. `read_market_resource(uri)` is the governed path to the
> same data — it is an ordinary tool, so it passes through and stays audited. The MCP Servers page
> shows *declared* and *via gateway* counts side by side rather than pretending they agree.

## 7. Observability

Every MCP request that reaches the server is recorded with: timestamp, source, caller name and
version, method, tool or resource name, a truncated argument preview, status, error code, latency,
protocol version and trace id.

- **Fleet Activity** (right rail, chat page) — live cross-host feed over SSE.
- **Audit Log** — filterable history with per-row inspection and a summary strip.
- **MCP Servers** — gateway status, capability surface, callers seen in the last hour, and
  the **editable tool allowlist**.

### Editing the tool allowlist

The **MCP Servers** page lists every tool the server exposes with a permit/block
toggle. Blocking a tool means the gateway refuses the call before it ever reaches
the server — that is the governance boundary, not a UI nicety.

Two things the page states rather than hides:

- **Saving writes the gateway's config file; it is not yet in force.**
  agentgateway reads its config only at startup, so a save is followed by a
  banner telling you to restart it (`python3 scripts/dev.py gateway`). Verified:
  after blocking `sector_ranking` and restarting, a call through the gateway
  fails with `Unknown tool: sector_ranking`.
- **Unsaved toggles are not policy.** Pending edits are marked, and nothing is
  written until you press save.

Edits go to `policies.mcpAuthorization` in
`backend/mcp_server/gateway/config.yaml`, line-wise so every comment in that file
survives. Unknown tool names are rejected rather than written.

This lets a browser with no authentication edit a security policy — a deliberate
trade for a localhost PoC. Turn it off with:

```ini
ALLOW_POLICY_EDIT=false
```

The page then renders read-only and the endpoint returns `403`.

**Attribution** comes from `io.modelcontextprotocol/clientInfo`. A caller that sends nothing usable
is recorded as `unknown` — never guessed. Override the mapping without touching code:

```bash
MCP_SOURCE_PATTERNS='{"my-host":"my-label"}'
```

**Conversation attribution is partial by design.** MCP defines no conversation identifier in any
revision, so external hosts cannot supply one; those rows show `n/a`. This repo's own client injects
its conversation id via the W3C `baggage` key, so Control Room rows link back to the exact chat.
Calls with no identifier are grouped into **episodes** by idle gap — a reading aid inferred from
timing, never presented as a conversation.

## 8. Develop

Run these from `backend/` — that is where the pytest and ruff configuration
lives, and neither tool finds it from the repository root:

```bash
cd backend && .venv/bin/python -m pytest
```

```bash
cd backend && .venv/bin/ruff check .
```

100 tests cover protocol conformance, transport rules, the tool surface, REST
parity, the registry contract, attribution, retention and the client. The default
run is hermetic — no gateway, no credentials, no network. Two suites opt in:

```bash
cd backend && .venv/bin/python -m pytest -m gateway
```

7 tests against a **running** agentgateway: that the revision survives the hop,
that tools are proxied, that resources and prompts are not, and that a caller's
identity reaches the audit log. Start the stack first; without it they skip with
a message naming what is missing.

```bash
cd backend && .venv/bin/python -m pytest -m llm
```

3 tests driving the real configured model through `/agui`, asserting the event
contract rather than the wording: exactly one usage event per run, a tool
actually executed, and no reasoning content forwarded. Needs `LLM_API_KEY`
(§2.4); skips loudly without it.

### Adding a module

Drop a package under `backend/modules/` exporting one `MODULE = ModuleSpec(...)` and it is wired
into REST, MCP and the seeder with **no other file edited**. `tests/test_registry.py` enforces that
by creating a module at test time and asserting it appears. If you ever have to edit a shared file
to add a module, that is a bug in the registry, not in your module.

See [CLAUDE.md](CLAUDE.md) for ground truth and the SDLC, [SPECS.md](SPECS.md) for acceptance
criteria, [MIGRATION_PLAN.md](MIGRATION_PLAN.md) for why the architecture looks like this, and
[DESIGN.md](DESIGN.md) for the UI spec.

## 9. Troubleshooting

| Symptom | Cause |
| :--- | :--- |
| `Cannot reach the MCP server at http://127.0.0.1:3111/mcp` | The gateway is not running. `python scripts/dev.py gateway`. |
| Chat replies "LLM_API_KEY is not set" | Expected without credentials. Everything except the chat still works. |
| Audit Log is empty | Nothing has called the server yet, or a host is wired directly to `:8000` and bypassing the gateway. |
| `421 Misdirected Request` on `/mcp` | The `Host` header is not a loopback address. The endpoint binds to localhost and validates `Origin`/`Host` — mandatory for this transport. |
| Host connects but resources and prompts are missing | The gateway does not proxy them; use `read_market_resource`. See §6. |
| `-32022 Unsupported protocol version` | Something is speaking an older MCP revision. This server is 2026-07-28 only; set `STRICT_PROTOCOL=false` to also accept the legacy handshake. |
| macOS: "cannot be opened because the developer cannot be verified" | Gatekeeper quarantined the gateway binary. See §2.3. |
